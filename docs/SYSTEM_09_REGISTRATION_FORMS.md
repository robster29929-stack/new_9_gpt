# ระบบ 09 — สมัครสอบนักธรรมและธรรมศึกษาผ่าน Excel

สถานะเอกสาร: UI prototype TEST_ เท่านั้น · ปรับปรุง 15 ตุลาคม 2026

## แบบบัญชีที่แยกในหน้าจอ

| ประเภทสมัคร | แบบบัญชีตามหน้า download ที่ตรวจพบ | ผู้สมัครตามคำอธิบายแหล่ง | หมายเหตุ |
| --- | --- | --- | --- |
| นักธรรมชั้นตรี | ศ.1 | ภิกษุ/สามเณร | ผู้ใช้ระบุ “ศ.1–2”; หน้าแบบฟอร์มปัจจุบันที่ตรวจพบระบุ ศ.1 สำหรับชั้นตรี จึงใช้ ศ.1 ในตัวเลือกและเปิด issue ให้เจ้าของยืนยันความต่าง |
| นักธรรมชั้นโท–เอก | ศ.2 | ภิกษุ/สามเณร | ชั้นโทและเอกต้องอยู่ในค่าชั้นของแต่ละแถว แม้เลขแบบบัญชีเหมือนกัน |
| ธรรมศึกษาชั้นตรี | ศ.5 | นักเรียน/นักศึกษา/คฤหัสถ์ทั่วไป | แหล่งเรียกแบบสมัครธรรมศึกษาชั้นตรี |
| ธรรมศึกษาชั้นโท–เอก | ศ.6 | นักเรียน/นักศึกษา/คฤหัสถ์ทั่วไป | ชั้นโทและเอกต้องแยกค่าชั้นของแต่ละแถว |

รายการข้างต้นเป็นการอ่านชื่อแบบจากหน้า download ของสำนักงานแม่กองธรรมสนามหลวง ไม่ได้ยืนยันรุ่นไฟล์ Excel/คอลัมน์ที่หน่วยงานจะรับในรอบถัดไป

## Workflow ที่ทำได้ใน prototype

1. เลือกประเภทบัญชี/ชั้นสอบหนึ่งในสี่รายการก่อนเลือกไฟล์
2. อ่าน `.xlsx`/`.csv` ใน browser แล้วตรวจหัวคอลัมน์กลาง: ชื่อผู้สมัคร, ประเภทผู้สมัคร, ชั้น, หน่วยงาน และรหัสรอบสอบ; ตรวจว่า class TEST_ ตรงกับโปรแกรมและชั้นของแบบที่เลือก
3. preview แถว, ตรวจข้อมูลว่าง/ซ้ำ และบังคับค่า TEST_ ก่อนเปิดปุ่ม commit
4. รับเฉพาะหัวคอลัมน์กลาง 5 ช่องที่รู้จัก; ปฏิเสธหัวคอลัมน์ซ้ำ/คอลัมน์อื่น และค่าที่ไม่มีหัวคอลัมน์ เพื่อไม่ให้ข้อมูลนอกแบบทดสอบผ่านโดยไม่ถูกตรวจ
5. เปลี่ยนประเภทบัญชีแล้วล้าง preview เดิม เพื่อไม่ผูกไฟล์กับแบบผิดรายการ
6. commit หลังยืนยันเก็บผลเฉพาะใน browser memory; ไม่มีเลขสอบ ผลสอบจริง หรือการส่งข้อมูลออกจาก browser

ไฟล์ `TEST_exam_signup_template.xlsx` เป็น **แม่แบบกลางเพื่อทดสอบการอ่านไฟล์เท่านั้น** ไม่ใช่แบบ ศ.1/ศ.2/ศ.5/ศ.6 ฉบับทางการและยังไม่เทียบคอลัมน์จริง

## กติกาข้อมูล

- ใช้ `Person`, `Organization`, `ExamSession` ร่วมกับระบบอื่น; ไม่สร้างทะเบียนบุคคลหรือสนามสอบซ้ำ
- เลือกประเภทผู้สมัคร/ชั้น/แบบบัญชีเป็น metadata แยกจากบัญชีผู้ใช้และสิทธิ์
- ป้องกันไฟล์ซ้ำด้วย idempotency key และ unique constraints; commit production ต้อง recheck role+scope ที่ server, validate form revision, transaction, audit, optimistic lock และ maker-checker ตาม policy ที่องค์กรยืนยัน
- Public read/export ใช้ release/field allowlist ที่ได้รับอนุมัติ; ไฟล์ผู้สมัครและช่องทางติดต่อเป็น private data
- ห้ามเติมเลขสอบ, ผู้อนุมัติ, วันสอบ, ผลสอบ, คะแนน, รายชื่อจริง หรือการเซ็นรับรองขึ้นเอง

## TO VERIFY

- ความหมายของคำขอ “นักธรรมชั้นตรี ศ.1–2” เทียบกับหน้าแบบฟอร์มที่ตรวจพบซึ่งระบุ ศ.1
- ไฟล์ Excel ทางการรุ่นปัจจุบันของทั้งสี่ชนิด, sheet name, column order, required/optional fields, formats และฟิลด์แยกชั้นโท/เอก
- สิทธิ์บัญชีผู้ใช้/หน่วยงานในการ import, ขอบเขตองค์กร, รอบเปิดรับ, การแก้/ยกเลิก/เพิ่มผู้สมัคร, รายการซ้ำข้ามสนาม และเส้นตาย
- วิธีออกเลขสอบ, ขั้นตอน checker/ผู้อนุมัติ, การแจ้งผล และสิทธิ์เข้าถึงไฟล์แนบ; ไม่กำหนดจากชื่อ role เอง
- การจัดการข้อมูลส่วนบุคคล, retention, secure download, malware scan, audit และการลบ/ถอนข้อมูล

เจ้าของที่ต้องยืนยัน: เจ้าของแบบบัญชี/ระบบสมัครสอบของสำนักงานแม่กองธรรมสนามหลวง, ผู้ประสานงานสนามสอบและสำนักเรียน, เจ้าของ ExamSession และเจ้าของ policy ข้อมูลส่วนบุคคล (ระบุผู้แทนจริง `TO VERIFY`).

ทดสอบด้วย `TEST_` เท่านั้น: ไม่เลือกแบบแล้ว upload ต้องถูกปฏิเสธ; เลือกสี่แบบได้; แถวชั้นสอบต้องตรงกับแบบ; เปลี่ยนแบบแล้ว preview ต้องถูกล้าง; หัวคอลัมน์ขาด/ซ้ำ/ไม่รู้จัก, ค่าที่ไม่มีหัวคอลัมน์, แถวว่าง/ค่าที่ไม่ใช่ TEST_/ชื่อซ้ำ/class mismatch ต้องปิด commit; ไฟล์ valid ต้องเปิดหน้าต่างยืนยันและ commit เฉพาะ session; reload แล้วข้อมูลไม่คงอยู่.
