# ระบบ 08 — สารบรรณออนไลน์

ปรับปรุง 2026-10-16 · ขอบเขตปัจจุบันเป็น prototype ใน browser memory ใช้ `TEST_` เท่านั้น

## เป้าหมาย

รองรับงานร่างและติดตามหนังสือสำคัญ/เอกสารแจ้งงานในเว็บไซต์เดียวกัน ใช้ Organization จากระบบ 02, บัญชีและ role/scope ส่วนกลาง และแนวคิด File กลางร่วมกัน ไม่สร้างทะเบียนหน่วยงานหรือบัญชีผู้ใช้ซ้ำ

## หน้าจอในต้นแบบ

- กล่องเอกสารทั้งหมด, กล่องรับ, กล่องส่ง, ร่าง และแจ้งงานออนไลน์ พร้อมค้นหาและ pagination
- สร้างร่างด้วยประเภทเอกสาร, ชั้นข้อมูลตัวอย่าง, หน่วยงานต้นทาง/ผู้รับจากทะเบียน Organization, ข้อความ `TEST_` และชื่อไฟล์ตัวอย่างที่ไม่ใช่การ upload
- จดหมายเวียนออนไลน์: เลือกหน่วยงานผู้รับจากทะเบียน System 02, ใช้ตัวแปรที่กำหนด, ดูตัวอย่างแยกรายผู้รับ แล้วสร้างร่าง `TEST_` แยกหนึ่งฉบับต่อหน่วยงาน
- ส่งร่างเข้ากล่องตัวอย่างและทำเครื่องหมายรับทราบตัวอย่าง โดยมี confirm; ทั้งสองการกระทำเปลี่ยนสถานะใน memory เท่านั้น
- เปิดรายละเอียดเอกสารทั่วไปได้; รายการจำกัดสิทธิ์/ลับจะแสดงเพียง metadata ที่อนุญาตใน UI, ซ่อนเนื้อหา/ไฟล์ และไม่ค้นเนื้อหา
- CSV/XLSX export มี field allowlist สำหรับ metadata; ชื่อเรื่องในรายการจำกัดสิทธิ์ถูก mask; ไม่มี body, ไฟล์, ลายเซ็น หรือรายละเอียดการติดต่อใน export
- บันทึกเหตุการณ์ TEST_ ใน audit list ของ session เมื่อสร้างร่าง ส่งในตัวอย่าง หรือรับทราบตัวอย่าง

จดหมายเวียนรับเฉพาะหน่วยงาน/แม่แบบ TEST_ และตัวแปร `{{organizationName}}`, `{{organizationId}}`, `{{province}}`, `{{examType}}`, `{{examSession}}`; ระบบตรวจแม่แบบและแสดงตัวอย่างก่อนสร้างหลายร่าง ผู้รับแต่ละรายได้ร่างแยก แต่ไม่มีการส่งออกหรือแจ้งผู้รับจริง

## วงจรเอกสารเป้าหมาย (รอยืนยัน)

ร่าง → ตรวจทาน/เสนอ → ลงนามโดยผู้มีอำนาจและบริการที่องค์กรยอมรับ → ออกเลขรับ/ส่ง → ส่ง/รับหรือส่งกลับ → รับทราบ → จัดเก็บ/ค้นย้อนหลัง

ชื่อขั้นตอน ผู้รับผิดชอบ ลำดับงาน delegation, เลขทะเบียน, สถานะทางการ และหลักฐานทางกฎหมายยัง `TO VERIFY`; แผนภาพใน UI เป็นแนวทางออกแบบเท่านั้น ระบบต้นแบบไม่ทำขั้นตรวจ อนุมัติ ลงนาม ออกเลข หรือส่งเอกสารจริง

## โครงข้อมูลเสนอสำหรับระบบจริง

ใช้ `Person`, `UserAccount`, `Organization`, `File` และ `ExamSession` กลางที่มีอยู่/กำหนดใน data dictionary ส่วนกลาง แล้วสร้างระเบียนสารบรรณที่อ้างอิง foreign key ไม่คัดลอกข้อมูลบุคคลหรือหน่วยงานลงตารางใหม่

- `CorrespondenceItem`: รหัสภายใน, ประเภท, หน่วยงานต้นทาง/ปลายทาง, ชั้นข้อมูล, สถานะ workflow, revision ปัจจุบัน, วันมีผล และวันบันทึก
- `CorrespondenceRevision`: เนื้อหาแต่ละฉบับแบบ immutable พร้อม provenance และเหตุผลแก้ไข; การแก้เอกสารสร้าง revision ใหม่
- `CorrespondenceRecipient`: ผู้รับ/หน่วยงานตามรอบส่งและขอบเขต, สถานะรับ/ตอบรับ/ตีกลับตาม policy ที่ยืนยันแล้ว
- `CorrespondenceFileLink`: อ้างถึง File กลางพร้อม hash, classification และสิทธิ์อ่าน/ดาวน์โหลด; ไม่เก็บ public URL ให้ไฟล์จำกัดสิทธิ์
- `CorrespondenceRouteEvent` และ `AuditEvent`: append-only, actor, action, scope, revision, source, recorded_at และ effective_at แยกกัน
- ใช้ transaction, optimistic lock, unique constraints, idempotency key และ outbox สำหรับการส่ง/แจ้งเตือน; ตรวจสิทธิ์ที่ server, database/RLS, Storage และ worker ทุกครั้ง

ชื่อฟิลด์/สถานะ/เลขทะเบียนข้างต้นเป็นแบบร่าง ไม่ใช่ schema ที่อนุมัติแล้ว; ห้ามสร้าง migration จนเจ้าของงานและผู้ดูแลข้อมูลยืนยัน OQ-08

## สิทธิ์และการคุ้มครอง

ผลิตภัณฑ์จริงต้อง deny-by-default และแยก `read`, `edit`, `export`, `download`, `route`, `approve`, `sign`, `register`, `publish` ตาม role + scope + วันมีผล; ห้ามใช้อำนาจจากชื่อ role โดยไม่มี policy และห้ามใช้ `user_metadata` ตัดสินสิทธิ์ ตรวจสิทธิ์ใหม่ก่อนงานสำคัญและทุกครั้งก่อนส่งไฟล์ ห้าม public อ่านเอกสารจากฐานข้อมูลสด; เปิดเผยเฉพาะ approved release/field allowlist และมีถอน release/cache plan

ชั้นข้อมูลและรายการ `TEST_ทั่วไป`, `TEST_จำกัดผู้รับ`, `TEST_ลับจำลอง` มีไว้สาธิตหน้าจอเท่านั้น ไม่ใช่ระดับชั้นความลับที่องค์กรรับรอง เอกสารจริง/ไฟล์จริงต้องไม่ถูกอัปโหลดเข้า prototype นี้

## เกณฑ์ทดสอบ prototype

1. เปิดทุกกล่อง ค้นหา สลับแท็บ และเปลี่ยนหน้าได้
2. ร่างที่มีค่าจริง/ไม่ขึ้นต้น `TEST_` หรือเลือก Organization ที่ไม่มีในทะเบียนถูกปฏิเสธ
3. ยกเลิก confirm แล้วสถานะไม่เปลี่ยน; ยืนยันส่งเปลี่ยนเฉพาะ `TEST_ส่งจำลอง` และไม่มีเลขทะเบียน/การแจ้งผู้รับจริง
4. รับทราบได้เฉพาะรายการ incoming ที่รอรับทราบ; ทำซ้ำแล้วไม่เปลี่ยนซ้ำ
5. รายการจำกัดสิทธิ์ไม่แสดง body/ไฟล์ใน list, detail, search, CSV หรือ XLSX
6. Reload แล้ว draft/event ใน memory ไม่คงอยู่; prototype ไม่มี account, server authorization, database, Storage, actual signature, email, LINE หรือ external dispatch
7. จดหมายเวียนปฏิเสธตัวแปรที่ไม่รู้จัก/เนื้อหาที่ไม่ใช่ `TEST_`; แสดงค่าที่แทนแยกรายหน่วยงานก่อนยืนยัน
8. เมื่อยืนยัน จดหมายเวียนสร้างร่างคนละรายการต่อผู้รับและยังอยู่ในกล่องร่าง; ไม่มีการส่งจริง

## เจ้าของข้อมูลและงานค้าง

เจ้าของสารบรรณ/ทะเบียนหนังสือ, ผู้มีอำนาจกำหนด workflow, เจ้าของข้อมูลบุคคลและหน่วยงาน, ผู้ดูแล IT/security, ผู้ดูแล Storage, privacy และผู้มีอำนาจลงนามต้องระบุผู้แทนจริงและส่งหลักฐานตาม `docs/OPEN_QUESTIONS.md` ก่อนพัฒนา backend, migration, รับเอกสารจริง หรือเปิดใช้จริง
