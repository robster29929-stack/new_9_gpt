# คู่มือทดสอบต้นแบบ (ภาษาไทย)

## ข้อควรทราบ

ใช้ข้อมูลที่ขึ้นต้น `TEST_` เท่านั้น ห้ามใส่รายชื่อจริง ผลสอบจริง งบจริง หนังสือจริง ที่อยู่จริง หรือเบอร์ติดต่อจริง ข้อมูลไฟล์จะถูกอ่านในเบราว์เซอร์และเก็บใน memory ของหน้าเว็บจนกว่าจะ reload ไม่มี backend หรือบัญชีผู้ใช้จริง

## ปุ่มนำทางและออกจากโหมดตัวอย่าง

1. อยู่หน้าใดก็ได้แล้วกด **กลับขึ้นด้านบน** ที่มุมขวาล่าง ปุ่มควรเลื่อนกลับจุดบนสุด
2. เปิดเมนูระบบย่อย ตรวจว่ามีปุ่ม **ย้อนกลับ** และกดแล้วกลับหน้าก่อนหน้า; หน้าแรกไม่มีปุ่มนี้
3. กด **ออกจากระบบ** แล้วลองยกเลิก จากนั้นเปิดอีกครั้งและยืนยัน; ควรออกสู่หน้าจบโหมดตัวอย่างและล้างข้อมูล TEST_ ชั่วคราว
4. กด **กลับเข้าสู่โหมดตัวอย่าง TEST_** เพื่อเริ่ม session จำลองใหม่ การทดสอบนี้ไม่ใช่ authentication/logout จริง

## เปลี่ยนหน้ารายการจำนวนมาก

รายการในระบบ 01–08, คลังชั้นเรียนบาลี, ตารางกำหนดสิทธิ์ และ preview Excel ของระบบ 09/เมนูนำเข้าแสดงครั้งละไม่เกิน 25 แถว มีตัวควบคุมด้านล่างขวาของตาราง:

1. กด **หน้าแรก**, **‹**, **›**, และ **หน้าสุดท้าย** เพื่อตรวจการเลื่อนไปต้นรายการ, ย้อนหนึ่งหน้า, เดินหน้าหนึ่งหน้า และไปท้ายรายการ
2. พิมพ์เลขในช่อง **ไปหน้า** แล้วกด Enter หรือออกจากช่อง ระบบจะไปหน้าที่ระบุ; เลขต่ำ/สูงกว่าช่วงจะถูกจำกัดให้อยู่ในหน้าที่มี
3. ค้นหารายการในระบบ 01–08 แล้วตรวจว่าค้นหาครอบคลุมระเบียนทั้งหมด ไม่ใช่เฉพาะ 25 แถวที่กำลังแสดง และตัวนับหน้ากลับไปหน้า 1
4. เปลี่ยนตัวกรองสถานะบุคคลหรือชั้นประโยค แล้วตรวจว่ารายการเริ่มที่หน้า 1 พร้อมจำนวนหน้าที่คำนวณใหม่
5. สำหรับทดสอบข้อมูลขนาดใหญ่ ให้ใช้ CSV ที่ทุกค่าขึ้นต้น `TEST_` เท่านั้น; preview Excel แสดงเลขแถวเดิมและไม่เปลี่ยนข้อมูลจนกดยืนยัน

## ผู้ใช้ บทบาท และสิทธิ์ (ระบบจำลอง)

1. เปิดเมนู **ผู้ใช้ บทบาท และสิทธิ์** และตรวจผู้ใช้/role ที่เป็น TEST_ รวม role ผู้ดูแลระบบสูงสุด
2. เลือกผู้ใช้ role ระบบ ระดับขอบเขต และค่า `TEST_`; เลือกสิทธิ์ราย action แล้วบันทึก
3. ตรวจ assignment ใหม่ในตาราง ตรวจ scope ระดับส่วนกลาง/ภาค/จังหวัด/องค์กร/สนามสอบ และการแสดงสิทธิ์แยก action
4. ยืนยันข้อความเตือนว่า role/scope นี้อยู่ใน memory และยังไม่ถูกบังคับที่ server/ฐานข้อมูล

## นำเข้า/ส่งออก Excel

1. เปิดทะเบียนข้อมูลระบบ 01–08 แล้วเลือก **ส่งออก Excel**; ตรวจว่าไฟล์เป็น `.xlsx` และไม่มีช่องทางติดต่อจำกัดสิทธิ์ของระบบ 01
2. เปิด **นำเข้า Excel** เลือกระบบที่ตรงกับไฟล์ แล้ว preview จำนวนแถวและ validation
3. ทดสอบไฟล์รหัสระเบียนเดิม: ปุ่มนำเข้าต้องแสดงจำนวนเขียนทับและเปิดหน้าต่างยืนยัน; กด **ยกเลิก** แล้วข้อมูลเดิมต้องไม่เปลี่ยน
4. ทำซ้ำและกดยืนยัน: แถวที่มีรหัสเดิมแก้ไขใน memory; แถวรหัสใหม่เพิ่มใน memory
5. ทดสอบคอลัมน์ขาด ข้อมูลที่ไม่ใช่ TEST_ และรหัสซ้ำในไฟล์: ระบบต้องปฏิเสธก่อน commit

## ตรวจรับระบบ 01 — แยกตำแหน่งและแจ้งเตือนตำแหน่งซ้ำ

1. ในทะเบียนบุคคลตรวจว่าตารางแยกคอลัมน์ **ตำแหน่งทางการปกครอง** และ **ตำแหน่ง จศป. ฝ่ายการศึกษา**
2. เปิด **เพิ่มข้อมูล TEST_** ตรวจตัวเลือกตำแหน่งทางการปกครอง 12 รายการและ checkbox ฝ่ายการศึกษา 12 รายการ; เลือกฝ่ายการศึกษาได้หลายค่า
3. กรอกชื่อเดียวกับระเบียน TEST_ ที่มีอยู่ และเลือกฝ่ายการศึกษามากกว่า 1 ตำแหน่ง; ตรวจคำเตือนหลายตำแหน่งและคำเตือนชื่อซ้ำ/ตรวจทานตำแหน่ง ระบบไม่รวมบุคคลหรือปฏิเสธร่างอัตโนมัติ
4. ตรวจว่าการยืนยันร่างไม่มีตำแหน่งทั้งสองกลุ่มถูกปฏิเสธ และการเลือกอย่างน้อยหนึ่งตำแหน่งผ่านการตรวจตำแหน่งได้; ข้อมูลยังเป็น TEST_ และอยู่ใน memory เท่านั้น
5. ส่งออก Excel/CSV ระบบ 01 ตรวจสองคอลัมน์แยกกัน และตำแหน่งการศึกษาหลายค่าใช้ ` | ` คั่น; ตรวจว่าไม่มีช่องทางติดต่อหรือข้อมูลเหตุสถานะใน CSV
6. นำไฟล์ที่ส่งออกกลับเข้า preview; ตรวจว่าตำแหน่งหลายค่าถูกอ่านเป็นหลายรายการ และถ้าพบหลายตำแหน่ง/ชื่อซ้ำจะแสดงคำเตือนต่อแถวโดยไม่ถือเป็นผลอนุมัติ

## ตรวจรับระบบ 02 — หน่วยงานและสนามสอบ

1. เปิด **หน่วยงานและสนามสอบ** ตรวจประเภท TEST_ ทั้ง 10: สำนักเรียน, สำนักศาสนศึกษา, สำนักเรียนบาลีประจำจังหวัด, วัด, องค์กร, สถานศึกษา, สนามสอบบาลี, สนามสอบนักธรรมชั้นตรี, สนามสอบนักธรรมชั้นโท-เอก และสนามสอบธรรมศึกษา
2. ใช้ตัวกรองประเภทตรวจว่าสนามสอบนักธรรมชั้นตรีกับชั้นโท-เอกแสดงแยกกัน ใช้ตัวกรองจังหวัด แล้วตรวจว่าข้อมูลของแต่ละประเภทผูกกับรหัส/ชื่อรอบสอบ `ExamSession`
3. เปิดรายละเอียดสนามสอบ ตรวจที่ตั้ง และส่วนประธานสนามสอบ/ผู้รับข้อสอบที่มีที่อยู่ เบอร์โทร อีเมล และ LINE ID พร้อมข้อความ **จำกัดสิทธิ์**
4. ตรวจหน้า listing และคำค้นว่าไม่เผยช่องทางติดต่อหรือที่อยู่ส่วนบุคคล; ข้อมูลติดต่อแสดงเฉพาะในรายละเอียด/preview ที่ระบุคำเตือน และเป็น TEST_ เท่านั้น
5. เปิด **เพิ่มหน่วยงาน TEST_** ตรวจฟิลด์ที่อยู่และข้อมูลสนามสอบรายรอบ; ถ้าเลือกประเภทสอบต้องกรอกรอบสอบ ชื่อประธาน และชื่อผู้รับก่อนบันทึกใน memory
6. ส่งออก/ดาวน์โหลดแม่แบบ Excel ระบบ 02 ตรวจฟิลด์หน่วยงาน ที่ตั้ง รอบสอบ และข้อมูลประธาน/ผู้รับข้อสอบ รวมที่อยู่ เบอร์โทร อีเมล และ LINE ID จากนั้นลองนำกลับเข้า preview; ค่าที่ไม่ขึ้นต้น `TEST_` ต้องถูกปฏิเสธ
7. ยืนยันว่ารายชื่อทั่วประเทศและช่องทางติดต่อจริงยังไม่ได้โหลด ต้องใช้แหล่งทะเบียน/คำสั่งมอบหมายที่เจ้าของข้อมูลรับรองก่อนใช้งานจริง

## เปิดเว็บในเครื่อง

ต้องมี Python 3 แล้วสั่งจากโฟลเดอร์โครงการ:

```bash
python3 -m http.server 8080 --directory dist
```

เปิด `http://localhost:8080` ใน browser แล้วใช้เมนูด้านซ้ายทดสอบทั้ง 9 ระบบ

## กรณีตรวจรับต้นแบบ

1. เปิดหน้า “ภาพรวม” แล้วตรวจพบ 9 เมนูหลัก และข้อความเตือนว่าเป็นข้อมูลจำลอง
2. เปิดระบบ 01 ตรวจตำแหน่งและสังกัด; ตรวจว่าช่อง “ภาค” อยู่ถัดจากจังหวัดและมีตัวเลือก 1–18; เลือกตัวกรองขอย้าย ลาออก มรณภาพ/ตาย และลาสิกขา; เปิด “ดูรายละเอียด” เพื่อตรวจประเภทเหตุ วันบันทึก วันมีผล และหลักฐานจำลอง โดยไม่มีผลพิจารณาจริง; ยืนยันว่าเบอร์โทร อีเมล และ LINE ไม่แสดงในตาราง/ค้นหา/CSV แต่แสดงในส่วนรายละเอียด TEST_ จำกัดสิทธิ์; ทดลองสร้างร่างโดยเว้นช่องทางติดต่อได้ และค่าที่กรอกต้องขึ้นต้น `TEST_`
3. เปิดระบบ 02–08 ตรวจค้นหาจากช่อง “ค้นหาในรายการ TEST_” และเปิด “ดูรายละเอียด” โดยข้อมูลทั้งหมดต้องเป็น `TEST_`
4. ระบบ 03 ตรวจคลังนักธรรม ธรรมศึกษา และบาลีในเมนูเดียว; จำนวน 12, 36 และ 20 รายการตามลำดับ; ธรรมศึกษาต้องมี 9 ช่วงชั้น; กดเลือกชั้น/ประโยคและวิชา; เปิดแท็บแบบทดสอบก่อนเรียน/หลังเรียน แล้วกดปุ่มแต่ละแบบเพื่อยืนยันว่าระบบแสดงสถานะรอชุดที่รับรอง ไม่สร้างคำถาม เฉลย คะแนนเรียน หรือผลสอบจริง
5. ระบบ 06 ทดลองแท็บภาพรวม แผน/จัดสรร โอน ผูกพัน เบิกจ่าย คืนเงิน กระทบยอด และปิดงวด; ยืนยันยอดรวมคำนวณจาก TEST_ fixture, `จัดสรร - ผูกพัน = ยังไม่ผูกพัน`, `ผูกพัน - จ่ายจริง = ค้างจ่าย`, และจ่ายจริงไม่หักซ้ำจากวงเงิน
6. ระบบ 06 สร้างร่างด้วยข้อมูลข้อความ `TEST_`; ลองยอดทศนิยม รหัสซ้ำ ยอดผูกพันเกินวงเงิน และยอดจ่ายเกินผูกพันค้างจ่าย ต้องถูกปฏิเสธ; ยอด integer satang ที่ผ่านต้องอยู่ใน memory และมีสถานะร่าง ไม่ใช่รายการอนุมัติ
7. ระบบ 06 ตรวจกรองงวดและ pagination ทุกแท็บรายการ; หน้าปิดงวด/กระทบยอดต้องไม่แสดงผลปิดงวดหรือรับรองบัญชีจริง
8. ระบบ 07 ตรวจ 11 แท็บ ตั้งแต่ทะเบียน/Stock card/ขอจัดซื้อ/รับเข้า/เบิก/คืน/โอน/ยืม/ซ่อม/ตรวจนับ/จำหน่าย; ยืนยันข้อมูลแถวและ reference ทั้งหมดขึ้นต้น `TEST_`
9. ตรวจยอดต่อคลังและรวมจาก movement; เบิก/โอน/ยืมเกินยอดต้องถูกปฏิเสธ; reference ซ้ำต้องไม่สร้าง movement ซ้ำ; โอนต้องมีคู่เข้า–ออกและยอดรวมไม่เปลี่ยน
10. สร้างร่างขอซื้อผูก `TEST_BUDGET_*` แล้วตรวจว่าไม่ผูกพันเงิน; ตรวจนับที่มีส่วนต่าง ซ่อม และคำขอจำหน่ายต้องไม่เปลี่ยนยอด stock เอง
11. สร้าง/คืนยืม TEST_ แล้วตรวจยอดลด/เพิ่มจาก movement และสถานะคงค้างคำนวณจากรายการคืน; เปิด Stock card แล้วตรวจแหล่งที่มาของยอด
12. ดาวน์โหลด/นำเข้า Excel ของระบบ 07 ตรวจว่ามีเฉพาะ master data ไม่มีคอลัมน์จำนวนคงเหลือ; ยกเลิกการเขียนทับแล้วจำนวนจาก movement ต้องไม่เปลี่ยน; ส่งออก Stock card CSV ตรวจ reference และจำนวนเปลี่ยนแปลง
13. ตรวจ `docs/SYSTEM_07_SOURCE_PROFILE.md` และ `docs/OPEN_QUESTIONS.md`; ยังไม่มีการอนุมัติหรือหลักเกณฑ์จริงของเจ้าของพัสดุ/การเงิน
14. ระบบ 08 ตรวจแท็บเอกสารทั้งหมด/กล่องรับ/กล่องส่ง/ร่าง/แจ้งงาน, search และ pagination; เปิดรายการ `TEST_จำกัดผู้รับ` แล้วตรวจว่าเรื่อง เนื้อหา และไฟล์ถูกปกปิด
15. เปิดรายละเอียดทั่วไปและรายการจำกัดสิทธิ์; ตรวจ audit เป็น TEST_ เท่านั้น และไม่มีเลขทะเบียนหรือวัน/ลายเซ็นจริง
16. สร้างร่างด้วยค่า TEST_ แล้วส่งเข้ากล่องตัวอย่าง; ยกเลิก confirm ต้องไม่เปลี่ยนสถานะ และยืนยันเปลี่ยนเฉพาะ `TEST_ส่งจำลอง`

18. Export CSV/XLSX ระบบ 08 แล้วตรวจ metadata allowlist, mask เรื่อง restricted, ไม่มีข้อความ/ไฟล์แนบ; ห้ามเลือกเอกสารจริงหรือ upload ไฟล์จริง

20. ระบบ 09 ดาวน์โหลด `TEST_exam_signup_template.xlsx` แล้วอัปโหลด ตรวจ preview และจำนวนแถว
21. ทดลองไฟล์ CSV/Excel ที่ฟิลด์ว่าง, ชื่อซ้ำ, หรือค่าที่ไม่ขึ้นต้น `TEST_`; ระบบต้องแจ้งข้อผิดพลาดและปิดปุ่ม commit
