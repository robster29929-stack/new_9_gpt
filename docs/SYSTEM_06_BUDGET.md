# ระบบ 06 — บริหารงบประมาณ

สถานะ: **ต้นแบบ UX/TEST_ เท่านั้น** · ไม่ใช่ระบบบัญชีหรืออำนาจอนุมัติจริง

## เป้าหมาย

รวมการติดตามงบไว้ในเว็บไซต์เดียวและเชื่อมกับ Organization และผู้ใช้/สิทธิ์ส่วนกลาง โดยไม่สร้างบัญชีผู้ใช้หรือทะเบียนหน่วยงานซ้ำ ขอบเขตหน้าจอต้นแบบมี 8 ขั้นตอน:

1. ภาพรวม
2. แผนและจัดสรร
3. โอนงบ
4. ผูกพัน
5. เบิกจ่าย/จ่ายจริง
6. คืนเงิน
7. กระทบยอด
8. ปิดงวด

หน้าภาพรวมคำนวณตัวเลขจากรายการแผน `TEST_` ปัจจุบัน ไม่ใช้ค่ารวมที่เขียนตายตัว หน้ารายการแต่ละขั้นค้นดูตามงวด `TEST_PERIOD_` และมี pagination สำหรับรายการจำนวนมาก

## สูตรและการนับเงิน

- เก็บจำนวนเงินเป็น integer satang; แบบร่างรับเฉพาะจำนวนเต็มบวก ห้ามทศนิยมและ floating-point input
- `วงเงินยังไม่ผูกพัน = จัดสรร − ผูกพัน`
- `ยอดผูกพันค้างจ่าย = ผูกพัน − จ่ายจริง`
- จ่ายจริงเป็นส่วนหนึ่งของยอดผูกพัน จึงไม่หักจากวงเงินจัดสรรซ้ำเป็นครั้งที่สอง
- รายการโอนต้องแสดงต้นทาง/ปลายทางเพื่อไม่บวกเป็นเงินเพิ่มสองฝั่ง
- รายการคืนเงินที่ยังรอตรวจไม่ลดรายจ่ายหรือเพิ่มวงเงินในยอดสรุป
- ปีงบประมาณ งวดบัญชี ปีการศึกษา และปีปฏิทินเป็นคนละมิติ; ตัวอย่างใน UI ใช้รหัส `TEST_FY_001` และ `TEST_PERIOD_01/02`

ค่าตัวอย่างสรุปปัจจุบันจากแถวจำลอง 3 แถว: จัดสรร 1,600,000.00 บาท; ผูกพัน 540,000.00 บาท; จ่ายจริง 270,000.00 บาท; ยังไม่ผูกพัน 1,060,000.00 บาท; ค้างจ่ายภายในยอดผูกพัน 270,000.00 บาท ตัวเลขทุกจำนวนเป็นข้อมูลทดสอบเท่านั้น

## แบบร่างและข้อจำกัดของต้นแบบ

- ผู้ใช้สร้างร่างเฉพาะใน memory ของ browser; ข้อความและรหัสต้องขึ้นต้น `TEST_`
- ตรวจรหัสซ้ำและตรวจว่ายอดร่างผูกพันไม่เกินงบที่ยังไม่ผูกพัน, ยอดจ่ายไม่เกินผูกพันค้างจ่าย และยอดคืนเงินไม่เกินยอดจ่ายตัวอย่าง
- ไม่มีปุ่มอนุมัติ/ลงนาม, ไม่มีการโพสต์บัญชี, ไม่มีการจ่ายเงินจริง, ไม่มีการปิด/ล็อกงวด และข้อมูลหายเมื่อ reload
- รายการกระทบยอดและปิดงวดใช้ทดสอบการแสดงสถานะเท่านั้น; ไม่มีหลักฐานจากธนาคาร/บัญชีจริง
- import/export Excel ที่มีอยู่ใช้ชุดแผนตัวอย่าง ไม่ใช่รูปแบบรายงานทางการ; รายการขั้นอื่นยังไม่มีการนำเข้าข้อมูลจริง

## เป้าหมายเมื่อทำระบบจริง

ต้องตกลงแบบข้อมูล revision, dimension ของแหล่งเงิน/ปีงบ/หน่วยงาน/โครงการ/บัญชี, แหล่ง truth ของยอดเงิน, workflow และผู้ตรวจ/ผู้อนุมัติ, วันมีผลและวันบันทึก, เอกสารหลักฐาน, การแบ่งงวด, การแก้ไข/กลับรายการ, การต่อระบบบัญชี/ธนาคาร, audit, optimistic lock, transaction, idempotency, outbox, retention, สิทธิ์อ่าน/แก้ไข/ส่งออก/อนุมัติ และการถอนรายงานที่เผยแพร่ ก่อนเริ่ม migration หรือเชื่อมระบบการเงินจริง

## เกณฑ์ทดสอบต้นแบบ

- ยอดสรุปตรงกับผลรวมแถว `TEST_` และคำนวณด้วยสตางค์จำนวนเต็ม
- จ่ายจริงไม่ทำให้ยอดคงเหลือถูกหักซ้ำ; ยอดค้างจ่ายแสดงแยกจากวงเงินยังไม่ผูกพัน
- ทุกขั้นตอนเปิดดูรายละเอียด/กรองงวด/เปลี่ยนหน้าได้; คำขอร่างมีรหัส TEST_ และอยู่ใน memory เท่านั้น
- ปฏิเสธทศนิยม ยอดไม่ปลอดภัย รหัสซ้ำ และยอดเกินขอบเขตที่ตรวจได้ใน fixture
- ไม่แสดงคำอนุมัติ สถานะทางการ หรือเอกสารจริง

## ผู้รับผิดชอบที่ต้องกำหนด

ยังไม่ทราบผู้แทนหน่วยงาน/เจ้าของข้อมูลงบประมาณที่ได้รับมอบหมาย จึงระบุเจ้าของเชิงบทบาทไว้ใน `docs/OPEN_QUESTIONS.md` และยังไม่มีการอ้างอำนาจอนุมัติ
