# ระบบ 02 — ทำเนียบหน่วยงานและสนามสอบ

## สถานะ

หน้าจอต้นแบบใน private Site มีข้อมูล `TEST_` เท่านั้น ยังไม่ได้เชื่อมฐานข้อมูลหรือใช้รายชื่อ/ที่อยู่/ข้อมูลติดต่อจริง รายการตัวอย่าง 10 แถวครอบคลุม 10 ประเภท ได้แก่ สำนักเรียน สำนักศาสนศึกษา สำนักเรียนบาลีประจำจังหวัด วัด องค์กร สถานศึกษา สนามสอบบาลี สนามสอบนักธรรมชั้นตรี สนามสอบนักธรรมชั้นโท-เอก และสนามสอบธรรมศึกษา

โฟลเดอร์โครงการยังไม่มี BLUEPRINT, ERD, DATA_DICTIONARY หรือ SOURCE_PROFILE กลาง เอกสารนี้บันทึกขอบเขตและพจนานุกรมเฉพาะระบบ 02 ที่ยืนยันจากคำขอปัจจุบัน โดยไม่ถือเป็น schema หรือ policy ที่อนุมัติสำหรับ production

## ข้อมูลที่แสดง

| กลุ่ม | ฟิลด์ในต้นแบบ | ข้อกำหนด |
|---|---|---|
| หน่วยงาน/สถานที่ | รหัส, ชื่อ, ประเภท, พื้นที่/สังกัด, ที่อยู่, ตำบล, อำเภอ, จังหวัด, รหัสไปรษณีย์ | รหัสและข้อมูลทดสอบขึ้นต้น `TEST_`; ที่อยู่จริงต้องมาจากแหล่งที่เจ้าของรับรอง |
| รอบสอบ | ประเภทสอบ, รหัสรอบสอบ `ExamSession`, ชื่อรอบสอบ | ผูกผู้รับผิดชอบกับรอบสอบ ไม่อนุมานปีสอบ/วันสอบจาก fixture |
| ประเภทสนามสอบ | บาลี, นักธรรมชั้นตรี, นักธรรมชั้นโท-เอก, ธรรมศึกษา | นักธรรมตรีแยกจากนักธรรมโท-เอกทั้งประเภทหน่วยงานและประเภทสอบ |
| ประธานสนามสอบ | ชื่อ, ตำแหน่ง, ที่อยู่, เบอร์โทร, อีเมล, LINE ID | แสดงในรายละเอียดที่ระบุว่าจำกัดสิทธิ์; ค่าทดสอบเท่านั้น |
| ผู้รับข้อสอบ | ชื่อ, ตำแหน่ง, ที่อยู่, เบอร์โทร, อีเมล, LINE ID | ระบุรายสนามและรอบสอบ; ค่าทดสอบเท่านั้น |
| การทบทวน | สถานะจำลอง | ไม่ใช่สถานะอนุมัติหรือสถานะทางราชการ |

การค้นหาในทะเบียนไม่นำเบอร์โทร อีเมล LINE ID และที่อยู่ของบุคคลผู้ประสานงานมาเป็นข้อความค้นหา ตารางแสดงชื่อทดสอบ ส่วนรายละเอียดและ preview ของ Excel ระบุคำเตือนข้อมูลจำกัดสิทธิ์

## แบบจำลองข้อมูลสำหรับพัฒนาต่อ

ใช้ `Organization` ร่วมกับระบบอื่นเป็น master เดียว และแยกการรับผิดชอบสนามสอบออกเป็นความสัมพันธ์ตามรอบ:

- `Organization`: หน่วยงาน วัด สถานศึกษา หรือสถานที่สอบ พร้อมประวัติที่อยู่และรหัสอ้างอิง
- `ExamSession`: ประเภทการสอบและปีการศึกษาที่องค์กรยืนยัน
- `ExamSiteAssignment`: ผูก `Organization` กับ `ExamSession`; เก็บ revision และช่วงวันที่มีผล
- `ExamSiteContactAssignment`: บทบาทประธานสนามสอบ/ผู้รับข้อสอบ พร้อม `Person` และช่องทางติดต่อที่มี scope และสิทธิ์เฉพาะ
- การเผยแพร่สาธารณะใช้ approved release และ field allowlist; ถอน release ต้องล้าง cache ตามแผนที่องค์กรยืนยัน

หน้าจอต้นแบบเก็บฟิลด์ของ assignment แบบแบนในแถวเดียวเพื่อให้ทดลองกรอก/นำเข้า Excel ได้ง่าย จึงยังไม่ใช่การทำ normalization ของฐานข้อมูล production

## ประเด็น TO VERIFY

| ประเด็น | เจ้าของที่ต้องยืนยัน | ข้อมูล/หลักฐานที่ต้องใช้ |
|---|---|---|
| รายชื่อและประเภทหน่วยงานที่เป็น master | เจ้าของทะเบียนส่วนกลางที่องค์กรแต่งตั้ง | ไฟล์ทะเบียนล่าสุด, รหัสอ้างอิง, ผู้ดูแลข้อมูลและวันปรับปรุง |
| รายชื่อสนามสอบทั่วประเทศและที่ตั้ง | ผู้ดูแลสนามสอบของแต่ละประเภท | รายชื่อทางการที่ลงวันที่, สถานที่, ที่อยู่มาตรฐาน, รหัสสนาม และแหล่งต้นฉบับ |
| ผู้มีหน้าที่เป็นประธาน/ผู้รับข้อสอบในแต่ละรอบ | เจ้าของงานสอบที่องค์กรแต่งตั้ง | คำสั่ง/บัญชีมอบหมายที่ตรวจสอบได้, รอบสอบ, วันมีผลและผู้บันทึก |
| สิทธิ์ดู แก้ไข ส่งออก และเผยแพร่ช่องทางติดต่อ | เจ้าของข้อมูลและผู้รับผิดชอบด้านนโยบายข้อมูล | ตาราง role+scope+action, วัตถุประสงค์, ระยะเก็บ, audit และ field allowlist |
| ชื่อฟิลด์และแม่แบบ Excel ทางการ | เจ้าของแบบฟอร์ม/เจ้าของทะเบียน | แม่แบบพร้อม revision, data type, required/optional, validation และกฎรหัสซ้ำ |

ไม่มีการสร้างรายชื่อจริง คำสั่งมอบหมาย หรือข้อมูลผู้ติดต่อขึ้นเอง ข้อมูลจริงจะต้องผ่านการรับรองแหล่งที่มาและ policy ก่อนนำเข้าหรือเผยแพร่

## วิธีตรวจต้นแบบ

1. เปิด **หน่วยงานและสนามสอบ** และตรวจประเภททั้ง 10 กับตัวกรองประเภทและจังหวัด
2. ใช้ตัวกรองแยกสนามสอบนักธรรมชั้นตรีออกจากสนามสอบนักธรรมชั้นโท-เอก; เปิดแต่ละระเบียนและตรวจ ExamSession กับส่วนประธาน/ผู้รับข้อสอบ
3. ยืนยันว่าหน้ารายการและการค้นหาไม่แสดงโทรศัพท์ อีเมล LINE ID หรือที่อยู่บุคคลผู้ติดต่อ
4. ส่งออก Excel/CSV แล้วตรวจว่ามีฟิลด์สำหรับที่ตั้ง รอบสอบ และข้อมูลผู้ติดต่อ TEST_ (รวมที่อยู่ เบอร์โทร อีเมล และ LINE ID ของทั้งสองบทบาท); ทดสอบนำกลับเข้า preview
5. ใช้เฉพาะข้อมูลที่ขึ้นต้น `TEST_`; การเปลี่ยนแปลงอยู่ใน memory และหายเมื่อ reload

การทดสอบนี้ไม่พิสูจน์การบังคับสิทธิ์จริงหรือการปกป้องข้อมูลที่ server/ฐานข้อมูล
