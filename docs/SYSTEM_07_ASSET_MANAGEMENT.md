# ระบบ 07 — บริหารวัสดุและครุภัณฑ์

อัปเดต 2026-10-15 · ขอบเขตเป็น prototype ใน browser memory และใช้ `TEST_` เท่านั้น

## เป้าหมายและเมนู

ทำทะเบียนพัสดุร่วมกับหน่วยงาน/คลังที่เชื่อมกับ Directory ระบบ 02, รหัสแผนงบประมาณระบบ 06 และเอกสารระบบ 08 โดยไม่สร้างบัญชีผู้ใช้หรือข้อมูลหน่วยงานซ้ำ เมนูย่อยประกอบด้วย:

1. ทะเบียนและยอดคงเหลือ
2. Stock card / movement history
3. คำขอจัดซื้อและรหัสแผนงบประมาณที่เกี่ยวข้อง
4. รับเข้า
5. เบิก
6. คืน
7. โอนระหว่างคลัง/หน่วยงาน
8. ยืมและคืนยืม
9. ซ่อมบำรุง/ตรวจสภาพ
10. ตรวจนับ
11. คำขอจำหน่าย

## กฎยอดคงเหลือ

- `Asset` เก็บรหัส รายการ ประเภท คลัง/หน่วยงานเริ่มต้น และสถานะทะเบียน; จำนวนคงเหลือไม่ใช่ช่องแก้ไขของทะเบียน
- `StockMovement` เป็นรายการเพิ่มใหม่: รับเข้า/ยอดยกมาเป็นบวก; เบิก/ยืม/โอนออกเป็นลบ; คืน/คืนยืม/รับโอนเป็นบวก
- ยอดคงเหลือต่อพัสดุและคลังคำนวณจาก `sum(quantity_delta)` ของ movement ที่มีรหัสพัสดุและคลังเดียวกัน
- การโอนสร้าง movement ออกและ movement เข้าใน reference เดียวกันในขั้นเดียว และตรวจยอดต้นทางก่อนเขียนคู่รายการ
- การคืนเชื่อมกับ reference การเบิก/ยืมเดิม และตรวจจำนวนคงค้างก่อนสร้าง movement; การอัปเดตยอดยืมคงเหลือในหน้าจอคำนวณจากประวัติ movement คืน ไม่แก้แถวต้นทาง
- รหัสอ้างอิงซ้ำถูกปฏิเสธในชุด TEST_; ในระบบจริงต้องทำ unique constraint, transaction, idempotency key, optimistic lock, audit และตรวจสิทธิ์ใหม่ฝั่ง server/RLS/worker
- ขอจัดซื้อเชื่อมได้เพียง `TEST_BUDGET_*`; ยังไม่ผูกพันเงินหรือเป็นใบสั่งซื้อ การตรวจนับแสดงส่วนต่างแต่ไม่ปรับ stock ซ่อมไม่เปลี่ยนจำนวน และคำขอจำหน่ายไม่ตัด stock
- คลังย่อย/ตำแหน่งจัดเก็บในหน้าจอเป็นตัวอย่าง `TEST_`; hierarchy และนโยบายคลังจริงยัง `TO VERIFY`

## Excel และ Stock card

- Excel ของระบบ 07 จัดการเฉพาะ master data: รหัส รายการ ประเภท คลัง/หน่วยงานเริ่มต้น และสถานะ
- ปริมาณคงเหลือไม่อยู่ใน schema นำเข้าและไม่ถูกเขียนทับจาก Excel; ก่อนเขียนทับ master data มี preview และ modal ให้ยืนยัน/ยกเลิกผ่านกลไกกลาง
- CSV ทะเบียนแสดงยอดจาก movement ที่คำนวณใน session; CSV Stock card แสดงรหัส movement, reference, รหัสพัสดุ, ประเภท, จำนวนเปลี่ยนแปลง, คลัง และ reference ต้นทาง/คลังคู่
- ไม่มีเอกสารจัดซื้อ ใบรับ ใบเบิก ใบยืม ลายเซ็น เลขทะเบียน หรือการอนุมัติจริง

## เจ้าของและข้อที่ต้องยืนยัน

เจ้าของข้อมูลหลัก, ผู้ดูแลคลัง, เจ้าของงบ/การเงิน, ผู้ดูแลทะเบียนครุภัณฑ์, ผู้ตรวจสอบภายใน, ผู้ดูแลสารบรรณ และผู้แทนด้านความมั่นคงปลอดภัย/ข้อมูลส่วนบุคคล ต้องระบุผู้รับผิดชอบจริงและให้หลักฐานนโยบายใน `docs/OPEN_QUESTIONS.md` ก่อนเริ่ม backend หรือข้อมูลจริง ห้ามตีความชื่อบทบาทในหน้าจอว่าเป็นอำนาจอนุมัติ

ประเด็นขั้นต่ำ: กลุ่มพัสดุและรหัสมาตรฐาน, คลังและขอบเขต, หลักฐานและ revision, ซื้อ/ตรวจรับ/เบิก/คืน/โอน/ยืม/ซ่อม/ตรวจนับ/จำหน่าย, การคิดค่าเสื่อมและมูลค่า, การผูกพันและจ่ายเงินจริง, maker-checker, สิทธิ์ราย action, retention, การนำเข้าเดิม, audit และการเชื่อมระบบงบประมาณ/สารบรรณ

## ขอบเขตการทดสอบ

ชุด `node tests/smoke.cjs` ตรวจการคำนวณยอดจาก movement, ยอดรายคลัง, เบิกเกิน, รับเข้า, transfer คู่ที่ยอดรวมไม่เปลี่ยน, ป้องกัน reference ซ้ำ, ยืม/คืนยืม, stock card, การนับไม่ปรับยอด, ซ่อมไม่เปลี่ยนยอด, ขอซื้อ/จำหน่ายไม่เปลี่ยน stock, Excel master preview และยืนยันการเขียนทับแบบยกเลิก
